# Build Yarnaholic — A Premium Handmade Fashion & Crochet Ecommerce Website

Act as a senior product designer, ecommerce UX specialist, brand strategist, and full-stack developer. Design and build a polished, responsive ecommerce website for **Yarnaholic**, a handmade fashion and yarn crafts brand specializing in crochet clothing, accessories, gifts, and custom-made pieces.

This should look like a real, thoughtfully art-directed fashion brand that could launch commercially, not a generic ecommerce template or an AI-generated dashboard.

**Your priorities are:**
1. Exceptional UI/UX and a distinctive visual identity.
2. A beautiful product discovery and shopping experience.
3. A seamless custom-design request and made-to-order workflow.
4. Realistic demo products, images, prices, and functional interactions.
5. A maintainable architecture that can later connect to a real backend and payment provider.

Build the actual working application, not just a design mockup. Do not stop after creating the homepage.

---

## 1. Brand identity and art direction

### Brand positioning

Yarnaholic is a contemporary handmade fashion label built around creativity, craftsmanship, individuality, and the beauty of things made by hand.

The brand should feel:
- Warm, creative, and expressive.
- Feminine without being overly cute.
- Premium and editorial without feeling inaccessible.
- Handmade, but never amateurish.
- Modern, trustworthy, and culturally adaptable for a Ghanaian and international audience.

The brand sells both ready-to-buy pieces and made-to-order designs.

### Visual identity

Use this design system:

**Color palette**
- Deep burgundy: `#6B263D` — primary brand color.
- Dusty rose: `#D9A5AD` — secondary accent.
- Warm ivory: `#FAF7F2` — main page background.
- Soft cream: `#F0E8DD` — secondary surfaces.
- Charcoal: `#292522` — primary text.
- Muted taupe: `#8C8179` — secondary text.
- White: `#FFFFFF` — cards and clean surfaces.

Use burgundy sparingly for important buttons, selected states, and brand accents. Let the photography, cream backgrounds, and typography do most of the visual work.

**Typography**
- Use an elegant editorial serif such as DM Serif Display or Cormorant Garamond for large headlines and expressive brand moments.
- Use Inter or Manrope for body text, navigation, buttons, prices, and interface elements.
- Establish a clear hierarchy with generous line-height and comfortable readability.

**Design language**
- Editorial fashion layouts with strong photography.
- Generous whitespace and carefully controlled spacing.
- Large, immersive product images.
- Subtle borders, restrained shadows, and soft corner radii.
- Asymmetric image compositions where appropriate.
- Minimal, tasteful animations and hover transitions.
- Small yarn-inspired decorative details only where they add meaning.
- Consistent icons, spacing tokens, button styles, and form components.

Avoid excessive gradients, glassmorphism, giant rounded cards everywhere, unnecessary animations, cluttered layouts, and generic SaaS styling.

The final result should feel like an independent designer fashion label.

## 2. Technical implementation

First inspect the existing Replit project. Reuse its existing stack if it is appropriate instead of replacing working code unnecessarily.

If starting from scratch, use:
- React with TypeScript.
- Vite.
- Tailwind CSS.
- React Router.
- Lucide icons.
- Reusable components and a centralized design-token system.
- Local mock data for products, collections, reviews, and orders.
- Local storage for demo cart, wishlist, and customization drafts.
- A lightweight form-validation library such as Zod with React Hook Form, if useful.

Choose compatible, stable dependencies and keep the architecture straightforward.

Do not introduce a database, authentication provider, or payment integration merely to make the prototype appear sophisticated. Build the frontend with realistic demo data and clearly structured service boundaries so real integrations can be added later.

All visible primary actions must work. Do not create buttons that do nothing, fake successful payments, or pretend that orders have reached a real business.

## 7. Custom design request experience — A signature feature

Build a dedicated, polished custom-design experience that makes it easy for customers to commission something unique.

This is one of the most important parts of the website.

### Custom design landing page

Use a premium editorial layout with:
- A compelling hero image.
- A headline such as “Dream it. We'll stitch it.”
- An explanation of how custom orders work.
- Example custom creations.
- The request form.
- FAQs about pricing, production time, alterations, and deposits.

Clearly explain that a request is an enquiry, not a confirmed order. Pricing and production feasibility must be reviewed before confirmation.

### Multi-step custom request form

Build a guided, multi-step form with a visible progress indicator, back and continue buttons, validation, and a review step.

Keep the form elegant, easy to understand, and mobile-friendly.

**Step 1 — What would you like made?**

Offer selectable cards for:
- Dress.
- Top or crop top.
- Skirt.
- Cardigan or cover-up.
- Bag.
- Hat or headwear.
- Accessories.
- Home décor or gift.
- Other.

**Step 2 — Describe your design**

Collect:
- Design name or short title.
- Detailed description.
- Inspiration or occasion.
- Intended wearer, where relevant.
- Desired style or fit.
- Whether it is based on an existing Yarnaholic design or a completely new idea.

**Step 3 — Personalization**

Collect only relevant options based on the selected product:
- Preferred colors.
- Color palette.
- Size selection.
- Custom measurements, when applicable.
- Desired yarn texture or material preferences.
- Sleeves, neckline, length, or other relevant design details.
- Optional embellishments.

Use sensible conditional fields instead of showing every possible question to every customer.

Include a clear disclaimer that exact colors and final appearance may vary with available yarn and handmade production.

**Step 4 — Inspiration uploads**

Create a drag-and-drop upload area that supports multiple reference images in a real implementation.

For the prototype:
- Provide an upload interface with previews.
- Validate file type and file size.
- Allow users to remove selected images.
- Show a clear message if uploads are only previewed locally and are not transmitted or saved remotely.

Do not pretend files have been sent to the business when there is no upload backend.

**Step 5 — Budget and timeline**

Collect:
- Preferred budget range in GHS.
- Optional exact budget.
- Desired completion date.
- Occasion, if applicable.
- Flexibility on the delivery timeline.

Make it clear that the budget is a guide and the requested date is subject to confirmation.

**Step 6 — Contact details**

Collect:
- Full name.
- Email address.
- WhatsApp or phone number.
- Preferred contact method.
- City or delivery destination.
- Additional notes.
- Optional consent to receive updates about this request.

Validate all required fields and provide helpful, inline error messages.

**Step 7 — Review and submit**

Show a clear summary of the customer's choices before submission.

Allow the customer to return to previous steps and edit information.

On successful demo submission:
- Generate a demo request reference.
- Display a polished confirmation screen.
- Summarize the submitted details.
- Explain that the team will review the design and respond with feasibility, pricing, and timing.
- Provide a button to return to the shop.

Persist demo requests locally for the prototype, and explain that this is local demo storage, not a real business submission.

### Custom design dashboard concept

Prepare the data structure and UI components for a future customer-facing custom order tracker.

Possible statuses:
- Request received.
- Under review.
- Awaiting clarification.
- Quote sent.
- Awaiting approval.
- Deposit pending.
- In production.
- Quality check.
- Ready for dispatch.
- Completed.
- Cancelled.

These statuses should be designed as a future workflow, not automatically assigned as if real staff had processed the request.

### Important future integration

Structure the custom-order feature so it can later connect to:
- A database for permanent request storage.
- Secure image uploads.
- Email notifications.
- WhatsApp contact links.
- An owner-facing enquiry management dashboard.
- Quote approval and deposit payments.

Do not expose API keys or credentials in client-side code.

## 15. Accessibility, performance, and quality

Follow practical accessibility and production-readiness standards.

- Use semantic HTML.
- Label all form fields.
- Provide useful alt text.
- Ensure adequate contrast.
- Maintain visible keyboard focus.
- Support keyboard navigation in menus, dialogs, and galleries.
- Use accessible names for icon-only buttons.
- Respect reduced-motion preferences.
- Avoid layout shifts.
- Optimize image sizes and loading.
- Lazy-load below-the-fold images.
- Reserve image dimensions to prevent layout shifts.
- Avoid unnecessary dependencies.
- Avoid console errors and broken links.
- Ensure every route works on direct navigation.
- Include appropriate page titles and meta descriptions.
- Add Open Graph metadata where practical.
- Use structured product data only when the data is accurate.
- Create useful empty states, loading states, and error states.

Aim for strong Core Web Vitals and good Lighthouse accessibility, performance, SEO, and best-practices scores.
